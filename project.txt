Project 1: Permission-Aware Context Server (MCP Server)
My Opinion: This is the absolute winner if you want to land a high-paying AI Engineering / Enterprise AI role. The biggest hurdle companies face when adopting AI right now is data security (e.g., making sure an intern can't ask the AI for the CEO's salary). Very few engineers know how to solve this elegantly.

Is it worth doing? 100%. The Model Context Protocol (MCP) was recently released by Anthropic and is rapidly becoming the industry standard for connecting AI agents to enterprise data. Building an MCP server puts you on the cutting edge.
Difficulty (8/10): The hard part isn't the AI—it's the plumbing. You will need to learn how to propagate user identity (JWT tokens) from the AI client all the way down to a Postgres database, and configure Postgres Row-Level Security (RLS) to physically block unauthorized queries.
Feasibility: Very feasible. You don't need real corporate data; you can easily generate dummy data for "Finance", "HR", and "Engineering" using ChatGPT. You can build and test the entire thing locally on your machine before ever showing it off.
The "Wow" Factor: You can record a 60-second demo where you ask an AI, "What is the salary of the VP of Engineering?". Logged in as HR, the AI answers it. Logged in as Finance, the AI says "I don't have access to that information." Recruiters and hiring managers will instantly understand the value.


Let's build the MCP server!

We are building a "Permission-Aware Context Server" using the official Anthropic MCP Python SDK. The goal is to enforce Row-Level Security (RLS) down at the database layer so that the AI can only retrieve documents the user is authorized to see.

Here is what has already been completed in this folder:
1. `docker-compose.yml` is running a Postgres 15 database (`mcp_postgres`) on port 5432.
2. `init.sql` has created the `users`, `departments`, and `documents` tables. It has also enabled RLS on `documents` using the policy: `department_id = NULLIF(current_setting('app.current_department_id', true), '')::integer OR department_id = 4` (Public).
3. The Python virtual environment (`venv`) is activated and all dependencies (`mcp`, `fastapi`, `asyncpg`, `pyjwt`, etc.) are installed.

Please start Phase 3 and Phase 4:
1. Create a `server.py` file using FastAPI to simulate a login endpoint that generates a JWT.
2. Create the MCP Server instance in `server.py` with a `search_documents` Tool.
3. Use `asyncpg` to connect to the database. Before executing the `SELECT` query in the tool, ensure you execute `set_config('app.current_department_id', <jwt_claim>, false)` so Postgres enforces the RLS policy.
4. Expose the MCP server over SSE (Server-Sent Events) attached to the FastAPI app!
